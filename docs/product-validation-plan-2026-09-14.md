# 墨题产品验证执行方案（2026-09-14）

这份方案把下一阶段从“继续堆功能”切换为“验证合规内容是否能形成学习价值，并验证是否有人愿意付费”。它不替代真实用户、真实支付或法律授权证据；未发生的用户数据一律不填入结果栏。

## 一、当前判断

| 问题 | 当前证据 | 下一步判断 |
|---|---|---|
| 合规 | 公开库只有项目自建 AI 模拟题；旧考研回忆版/本地导出包保持 `local-only` | P0 继续保持，不允许为了增加题量恢复旧包 |
| 内容 | 12 套活跃模拟试卷、180 题、7,958 词汇；结构和 provenance 门禁通过 | 先验证内容是否足以支持一个完整复习周期，再决定是否扩题 |
| 工程 | 全量测试 `164 passed, 13 skipped`；正式参数严格门禁通过 | 进入稳定期，只修阻断问题和真实用户反馈，不启动横向功能线 |
| 商业 | 当前没有真实用户付费、转化、留存证据 | 以 10–20 名目标用户做有偿小规模内测 |

## 二、产品假设与验证方式

### 假设 H1：用户愿意为“错题闭环”付费

用户购买的不是题量，而是“做题 → 错因归纳 → 定向重练 → 到期复习”的持续反馈。首批内测只突出一个主承诺：每天 20 分钟，系统把当天错题转成下一次可执行的复习计划。

验证方式：邀请 10–20 名考研英语一/二目标用户，连续使用 7 天；至少完成首次练习、错题重做和一次 FSRS 到期复习。招募文案、知情边界和 Day 0–7 执行顺序见 [有偿内测招募与执行包](pilot-recruitment-kit-2026-09-14.md)。每位参与者在明确知情后支付一个人工确认的内测价，暂不接自动续费和复杂支付系统。

### 假设 H2：自建模拟题能够替代“必须有官方真题”的第一印象

用户必须在进入练习前看到“AI 模拟·非真题”和内容来源说明；反馈表单单独询问题目难度、解析可信度、题型覆盖和是否愿意继续使用。未经授权的真题不能用来填补短期题量缺口。

验证方式：每位内测用户至少完成 2 套模拟卷，并对每套题给出 1–5 分评价；抽查低分题，区分内容质量问题、难度不匹配和用户期待偏差。

### 假设 H3：本地优先是可感知的价值，而不是工程标签

用户应能在断网状态完成启动、练习、错题回收和词汇复习；AI 功能失败时仍能使用规则推荐。验证只记录是否完成，不记录题目正文、答案或 API Key。

## 三、7 天内测执行清单

参与者登记、每日闭环和 Day 7 访谈使用 [内测运营记录模板](pilot-operator-checklist-2026-09-14.md)；它只记录匿名编号和聚合状态，不替代真实知情同意、付款核对或法律义务。

| 时间 | 必做动作 | 通过标准 | 失败处理 |
|---|---|---|---|
| Day 0 | 招募并确认目标、设备、考试方向、知情同意和内测价 | 10–20 名真实目标用户，名单和同意记录可追溯 | 不足 10 人时先继续招募，不扩功能 |
| Day 1 | 首次启动、导览、完成第一套练习 | 首次练习完成率 ≥ 70% | 先修首屏、导入、题目说明和阻塞错误 |
| Day 2–3 | 错题重做与解释反馈 | 至少 50% 用户完成一次错题重做 | 优先修错题入口、解释可读性和推荐理由 |
| Day 4–6 | 到期复习、断网使用、模拟题评价 | 至少 40% 用户完成一次到期复习；断网链路无 P0 阻塞 | 修学习闭环，不增加新模块 |
| Day 7 | 访谈、续费/推荐意愿和退款原因记录 | 每位用户给出明确“愿意继续/不愿意继续”理由 | 按原因重写价值主张或下调范围 |

## 四、只看这些指标

首轮不追求虚荣指标，只记录以下聚合结果：

1. 激活率：完成首次练习的人数 / 入组人数。
2. 闭环完成率：完成“练习—错题重做—到期复习”的人数 / 入组人数。
3. 7 日留存：第 7 天仍主动打开并完成学习的人数 / 入组人数。
4. 付费转化：实际付款并完成首次练习的人数 / 收到内测邀请的人数。
5. 内容投诉率：被标记为答案、解析、题型或难度问题的题目数 / 被评价题目数。
6. 继续使用意愿：愿意以相同或更高价格继续的人数 / 完成访谈人数。

建议的首轮判定阈值：激活率 ≥ 70%、闭环完成率 ≥ 40%、7 日留存 ≥ 30%、付费用户中愿意继续者 ≥ 50%，且不存在未处理的合规或严重答案错误。阈值是决策规则，不是已经实现的成绩。

## 五、范围冻结与优先级

### 现在做

- 保持两个未授权题包 `local-only`，在公开 starter、Web、Windows、APK 和公开 ESQ 目录中持续阻断。
- 完成 Windows 公共代码签名、Android release keystore、真实 Android 设备运行验收，再重建并记录最终 artifact hash。
- 修复内测中直接阻断“首次练习、错题重做、到期复习、断网使用”的问题。
- 为模拟题补齐人工低分题复核和可追溯的反馈记录。

### 暂不做

- 不为增加题量重新引入未授权真题，不把模拟题包装成官方真题。
- 不扩展排行榜、证书、组织、自动续费、复杂支付和更多 AI 任务。
- 不以更多门禁、视觉打磨或压测轮次替代真实用户访谈和付费验证。

## 六、决策门

- **继续个人 Pro**：达到阈值，且用户明确把错题闭环视为付费理由。
- **调整定位**：使用频率尚可但付费弱，优先重写价值主张、定价和首屏，不扩题库规模。
- **暂停商业化**：内容投诉或留存明显失败，先修内容与学习闭环；不通过增加功能掩盖失败。
- **转机构试点**：只有出现明确学校/培训机构需求和至少 2 个付费试点，再重启组织、班级、报告和支付路线。

## 七、证据记录要求

每轮内测只保留：匿名用户编号、同意时间、设备/版本、完成事件、聚合反馈、付款状态和退出原因。管理员摘要接口只返回样本量、匿名编号数量、评分均值、分类计数和继续意愿计数，不返回反馈正文、联系方式或匿名编号。不得收集题目正文、答案、API Key 或未经同意的个人学习记录。发布前仍需单独保留 provenance、签名、设备运行和最终 artifact hash 证据。
