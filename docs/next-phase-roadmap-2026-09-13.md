## 已落地的核心闭环

- 本地刷题、判分、错题回收、词汇复习、FSRS 到期调度和重启恢复。
- ESQ 题库导入、离线数据库迁移、Windows 打包、Web 静态启动和 Android 构建流程。
- 诊断报告 → 薄弱点推荐 → 针对性练习的入口；AI 失败时保留本地规则和人工确认路径。
- AI 任务路由、结构化输出、缓存、配额、超时/重试和无模型降级。
- 本地指标采用用户同意后记录，包含首次启动、练习、错题、词汇、导入、AI、反馈、错误和安装事件。
- 今日计划现在为每项任务展示推荐原因、预期效果、证据状态和证据数量；个人数据不足时明确降级为规则推荐。

## 下一阶段优先级

### P0：从“可发布构建”进入“可负责分发”

1. **完成签名与真实设备闭环**
   - 为 Windows 安装包/portable 配置代码签名证书，为 Android 配置正式 release 签名；密钥只通过 CI secret 或本地安全凭据注入，不写入仓库。
   - 连接至少一台真实 Android 设备，完成安装、离线启动、练习、返回键、后台恢复、重启和迁移验证。
   - 预期效果：把当前“构建候选”升级为可负责分发的 release candidate。

2. **保持题包 provenance 门禁**
   - 当前两个公开包为项目生成的 CC0 模拟题，已通过 `--require-publishable-provenance --strict-quality`；不得把旧未授权题包恢复到公开资源。
   - 后续每个内容版本继续保留来源、许可证、人工抽检、AI diff 和发布样本证据。
   - 预期效果：降低版权、答案错误和“结构正确但内容不可发布”的运营风险。

3. **完成真实设备矩阵**
   - CI 保留 API 36 模拟器、APK 安装/启动/重启、Keystore、触控/键盘注入、通过 `adb emu rotate` 的旋转恢复和断网启动冒烟；上线前增加至少一台真实 Android 设备的触控、离线、返回键、后台恢复和数据库迁移记录。
   - Android 官方文档明确区分 JDK/AGP 兼容、模拟器和真实设备测试；项目不能只以 Gradle 构建成功作为移动端验收依据。
   - 预期效果：发现 WebView、触控、文件权限、生命周期和不同厂商系统的真实问题。

### P0.5：验证用户价值与付费意愿（功能冻结）

1. **先做 10–20 人有偿内测**
   - 目标用户限定为考研英语一/二个人用户；首轮用人工确认的内测价，不接自动续费，不把支付系统建设当成验证前提。
   - 7 天只验证“首次练习 → 错题重做 → 到期复习”的闭环，以及用户是否愿意继续付费。
   - 统一记录激活率、闭环完成率、7 日留存、实际付费、内容投诉和继续使用意愿；没有真实用户数据时不填目标达成结论。

2. **冻结横向功能扩张**
   - 只修阻断首次练习、错题重做、到期复习、断网使用和题目质量的问题。
   - 暂停排行榜、证书、组织、自动续费、更多 AI 任务和额外视觉打磨，直到内测给出明确付费理由。

3. **把模拟题价值说清楚**
   - 所有公开题面和题包都明确标注“AI 模拟·非真题”；不以未授权真题补充题量，不把模板生成内容包装成外部模型实时生成。
   - 逐题收集难度、答案、解析和题型反馈，低分题进入人工复核队列。

   详细执行表、指标定义和继续/调整/暂停决策门见 [产品验证执行方案](product-validation-plan-2026-09-14.md)。

### P1：提高学习结果可解释性和内容质量

1. **把学习闭环作为核心产品指标**
   - 继续观察“诊断 → 推荐 → 练习 → 提交 → 错题/词汇 → FSRS 复习”各环节的完成率。
   - 优先补充空数据、低数据量和重复练习场景的体验测试，避免把规则推荐误呈现为确定性诊断。

2. **建立题库抽样复核流水线**
   - 每次内容版本升级固定抽样题量，记录题干、选项、答案、题型、解析和媒体完整性。
   - AI 只能提出草稿或差异，人工确认后才改变正式题库。
   - 预期效果：将“导入成功”与“内容可教学、可发布”分开管理。

3. **AI 只服务于明确任务**
   - 保持错题归因、词汇标注、精讲和口语等任务的结构化契约；所有任务都应有超时、配额、缓存、人工确认和无模型降级。
   - 暂不扩展为泛聊天或高成本的默认调用，先以真实使用数据决定任务优先级。

### P2：用最小指标支持运营决策

- 只在用户同意后观察首次启动、首次练习、日活练习、错题复习、词汇复习、7 日留存、题库导入、AI 使用、反馈、错误和安装结果。
- 先服务考研英语一/二个人用户；组织、排行榜、证书、订单和复杂商业化不作为下一阶段主线，除非出现明确试点需求。
- 预期效果：降低范围蔓延，让内容质量、学习闭环和跨端稳定性先形成可复用能力。

## 当前分支与发布证据状态

- 本地 `main` 已包含拆分后的功能、题包替换和发布证据提交；当前工作树干净。
- `origin/main` 仍保留远程独有的巨型提交 `f912c76`，直接合并会删除本地新增的题包生成器、provenance 文档和发布产物证据。
- 当前处理原则：先以本地拆分后的历史作为候选发布基线，完成差异审查后再决定是否通过 PR 整合远程；不做 reset、强制覆盖或直接 push。
- r3 内容指纹与门禁结果见 `docs/content-release-evidence.md` 和 `docs/release-artifact-evidence-r3-2026-09-14.md`；旧 r1/r2 artifact hash 仅作为历史记录。
- 本地严格门禁应按发布工作流参数执行；release 数据库允许包含本地扩展，因此不要额外把 release/offline 文件 SHA-256 完全相同当作默认发布条件。两库应以内容计数、内容版本、provenance 和离线 seed smoke 共同判断。

## 本轮继续落地的事项

- 错题本已增加“今日复习全部”入口：将已到期 FSRS 队列一次性转成既有练习会话，保留原有判分、错题回收和 FSRS 更新链路。
- 已增加 `scripts/check_android_release_signing.ps1` 作为本地 release keystore 预检工具；它只检查路径、alias、密码变量和 `keytool` 可验证性，不保存或打印密钥。
- 已用契约测试和前端生产构建验证上述改动；真实 release keystore、真实 Android 设备和外部发布授权仍是 P0 未完成项。

## 发布前硬门槛

- [x] 当前公开模拟题包的 provenance 与质量证据齐全，`packages_not_publishable = 0`；旧未授权题包保持 local-only。
- [x] 程序/内容/离线版本与数据库指纹进入统一发布清单。
- [x] Windows 安装包、portable、Web 静态包和 Android 构建具备自动化检查；Android CI 还包含输入、旋转和断网启动 smoke。
- [x] 后端学习闭环和离线迁移有自动化回归。
- [ ] 至少一台真实 Android 设备完成触控、离线、重启和迁移验收。
- [ ] Windows/APK 正式分发签名、密钥保管和回滚记录完成；当前未签名 Windows 包和调试 APK 不等同于公开发行包。

## 本阶段不做的事情

- 不绕过题包来源/许可证/人工复核门禁。
- 不把 AI 输出直接写入正式题库。
- 不把本地没有设备的 Android 运行状态宣称为已验证。
- 不先建设组织、排行榜、证书、支付等外围能力来掩盖内容和学习闭环问题。
