## 问题 1：前端离线库自动迁移机制（核心问题）

### 根因

离线架构是「**首次启动 seed + IndexedDB 长期缓存**」（`frontend/src/services/db.ts`）：
首次启动把打包的 `frontend/public/question_bank.db` 完整读入内存并存进 IndexedDB，**之后每次启动优先使用 IndexedDB 里的副本**，不再读打包文件。而 schema 自动迁移只存在于后端 `initialize_database()`，仅作用于 `backend/data/question_bank.db`。

因此有两层缺口：
1. **源头缺口**：`frontend/public/question_bank.db` 没有任何自动迁移入口，新增表（如 `question_explanations`）不会出现在打包文件里；
2. **存量缺口**（比 review 描述的更深一层）：即使手动给打包文件补了表，**已装设备的 IndexedDB 旧副本依然没有新表**，离线查询照样失败——手动补表只是临时补救，无法到达存量用户。

### 方案：三层机制，单一事实来源

单一事实来源 = `backend/app/database.py` 的 `SCHEMA + _run_migrations`。以后新增表只需改这一个文件，重跑迁移脚本即可全链路跟上。

| 层 | 时机 | 机制 | 解决什么 |
|---|---|---|---|
| ① 构建期迁移 | 发布打包前 | `scripts/migrate_frontend_db.py` 对前端库执行与后端 `initialize_database()` **完全相同**的幂等迁移 | 新装设备的 seed 文件有新表 |
| ② 运行期自迁移 | 前端每次启动 | `offline_migrations.json` 清单随包发布，`db.ts` 启动时比对 `sqlite_master`，缺什么补什么，有变更才写回 IndexedDB | **存量设备**的 IndexedDB 旧副本自动升级 |
| ③ 清单自动生成 | 每次 ① 运行后 | 从迁移后的库 `sqlite_master` 导出全部 CREATE 语句，转成 `IF NOT EXISTS` 幂等形式写入 `frontend/public/offline_migrations.json` | 清单永不与后端 schema 漂移 |

配套修复：离线模式此前**没有** explain 路由（`api-adapter.ts` 的 `offlineGet` 未匹配返回 `{}`，有解析也显示「暂无解析」），已补上。

### 改动文件

- 新增 `scripts/migrate_frontend_db.py` — 构建期迁移 + 清单导出（`--check` 只读检查，`--all` 连后端库一起跑，全幂等）
- 新增 `frontend/public/offline_migrations.json` — 运行期迁移清单（78 对象，fingerprint `132f94a5203f`，随构建发布）
- 新增 `frontend/src/services/offline-migrations.ts` — `planMissingObjects()`（纯函数：比对清单与 `sqlite_master`，表先于索引保证依赖顺序）+ `applyOfflineMigrations()`（fetch 清单→补建→返回是否有变更）
- 修改 `frontend/src/services/db.ts` — `initDatabase()` 三条初始化路径（IndexedDB 恢复 / seed / 空库）汇合处统一执行自动迁移，失败不阻塞启动
- 修改 `frontend/src/services/api-adapter.ts` — 离线补 `/questions/{id}/explain` 与 `/explanations/coverage` 路由（缺表/脏数据兜底返回 `available:false`，不崩溃）
- 修改 `scripts/release_all.py` — 第 1 步前端 build 前插入 `python scripts/migrate_frontend_db.py`
- **补回** `backend/app/database.py`（SCHEMA 中 `question_explanations` 表 + 2 索引）与 `backend/app/main.py`（`explanations` 路由注册）——review 发现这两处任务 E 改动在两轮之间被还原过，本次已重新写入

### 验证（实测）

1. **构建期**：DROP `question_explanations` 后执行 `python scripts/migrate_frontend_db.py` → 输出「补建 3 个对象: index idx_question_explanations_model, index idx_question_explanations_updated, table question_explanations」，表结构、索引、数据全部恢复；重复执行报「已是最新（无变更）」（幂等 ✓）

   - 自动补建后表存在、2 索引存在 ✓
   - 与 api-adapter 相同 SQL 的离线 explain 查询正常返回解析 ✓
