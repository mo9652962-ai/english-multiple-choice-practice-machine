## 🟠 P1 · CI 生命线（今日全部修复，记录根因防复发）

### 2. lock 文件与 package.json 不同步 → CI 全红

**症状**：`npm ci` 失败，CI 三 job（前端/后端/隐私）**全部红**，从 9/20 起持续。
**根因**：`frontend/package.json` 声明 `vue ^3.5.42`，`package-lock.json` 锁定 `3.5.41` → `npm ci` 严格校验失败。
**修复**（`c85180b`）：`cd frontend && npm install` 重建 lock。
**教训**：改 `package.json` 依赖后**必须**同步跑 `npm install` 并提交 lock；`npm ci` 是严格模式，容不得漂移。
**Codex 检查**：改依赖 → 立即 `npm install` → 提交 lock → 本地 `npm ci --dry-run` 验证。

### 3. content-manifest.json 版本落后 → 3 个发布门禁测试失败

**症状**：`test_release_check` ×2 + `test_rebuild_public_content` 失败，**持续 6 天无人处理**。
**根因**：`CONTENT_VERSION` = `content-2026-09-20-r4`，但 `content-manifest.json` 仍是 `content-2026-09-14-r3`。
**修复**（`c85180b`）：manifest 的 `content_version` + `offline_seed_version` 同步到 r4。
**教训**：**发布版本三轨必须同时更新**——`VERSION`（程序）/ `CONTENT_VERSION`（题库）/ `OFFLINE_CONTENT_VERSION`（离线种子），漏一个门禁就红。
**Codex 检查**：改内容 → 同步三处 → `python -m pytest tests/test_release_check.py -q`。

### 4. SSRF 防护误伤代理 fake-ip 网段

**症状**：`test_ai_client.py::ChatCompletionRetryTests::test_retries_transient_503_and_returns_content` 失败。
**根因**：本机 FlClash fake-ip 把 `api.deepseek.com` 解析到 `198.18.0.79`（RFC2544 保留网段）→ SSRF 防护判定为内网地址拦截。
**修复**（`c85180b`）：`backend/app/services/ai_client.py` 放行 `198.18.0.0/15`。
**教训**：**fake-ip 代理环境会把公网域名解析到 198.18.0.0/15**——这是代理工具的通用行为（FlClash/Clash TUN），不是攻击特征。SSRF 白名单需包含此网段，否则本地开发 + CI 都会误报。
**Codex 检查**：写网络防护逻辑时，把 `198.18.0.0/15` 与 loopback 一起列入放行白名单。

### 5. 测试断言与实现常量脱节

**症状**：`test_rebuild_public_content.py` 期望删除 7 个包，实际只删 6 个。
**根因**：测试用的包 ID `cn.kaoyan2.simulated` 不在实现的 `UNPUBLISHABLE_PACKAGE_IDS` 名单里。
**修复**（`c85180b`）：测试改用真实存在的 `cn.kaoyan2.2025.cloze`。
**教训**：**测试数据必须来自真实常量/真实库**，不能凭想象编 ID；改名或调整名单后要同步测试。
**Codex 检查**：写涉及名单/常量的测试时，先 `python -c "from <mod> import CONST; print(CONST)"` 确认真实值。

### 6. android.yml 两处必败（长期红）

**症状 A**：`setup-java cache: gradle` 失败（12-15s 就挂）。
**根因**：`frontend/android/` 是 `npx cap add android` 生成的（被 gitignore），checkout 时无 gradle 文件。
**修复**（`f0f97a2`）：移除 `cache: gradle`，缓存交给 `gradle/actions/setup-gradle`。

**症状 B**：`Install or require verified release content inputs` 失败。
**根因**：离线种子库 `frontend/public/question_bank.db` 被 `*.db` 全局 gitignore，但 android.yml 每次 push 都强制要求它 → 必然失败。
**修复**（`12e1a2f`）：android workflow 改为 **tag / workflow_dispatch 触发**（构建依赖受控内容输入，push 时本就无输入）。
**配套**（`fb803a0` + `8ec3888`）：种子库入库（gitignore 例外）+ 隐私扫描白名单。
**教训**：**CI workflow 的触发条件必须与它依赖的输入匹配**——依赖受控内容（需人工授权/不在仓库）的构建，不能挂在每次 push 上。

**现象**：`CONTENT_VERSION` 与 manifest 差了 6 天才被发现（见问题 3）。
**教训**：三轨版本应加**自动化门禁**（已有 `tests/test_release_check.py`，但 CI 因问题 2 全红而没跑到）。

**事实**：`backup-before-merge`（190 独有 commit）、`backup/giant-f912c76`、`backup/pre-split-f912c76`、`feat/v2-release-closeout`、`release/v2.1.3-content-r1`。
**修复**：先打 tag 固化引用（`backup-archive/*`）再删分支，防 GC 回收后不可恢复。
**教训**：清理分支前**先打 tag**——tag 保留 commit 可达性，分支可以安全删。

## 🔵 P3 · 文档站（second-brain，今日修复）

### 10. MkDocs 站点实际是坏的（长期未被发现）

**症状**：线上 `mo9652962-ai.github.io/second-brain/` 根路径无 index.html（404），只有 2 个页面。
**根因**：`mkdocs.yml` **未设 `docs_dir`** → MkDocs 默认读 `docs/`（仅 3 个文件），而 `nav` 里 20 个条目全指向仓库根的其他路径 → 全部 "not found"，构建"成功"但内容是空的。
**修复**（`5964d7f`）：`docs_dir: !ENV [MKDOCS_DOCS_DIR, docs]`，CI 用 `git ls-files` 组装全库 tracked `*.md` 传入 → **2 页 → 1044 页**。
**教训**：**构建"成功"不等于产物正确**——必须断言关键产物存在（`test -f _site/index.html`）并检查页面数量。

### 11. `git ls-files` 对非 ASCII 路径加引号 → CI cp 失败

**症状**：CI `Assemble docs sources` 失败：`cp: cannot stat '"META/\347\273...md"': No such file or directory`。
**根因**：`git ls-files` 默认 `core.quotePath=true`，中文/特殊字符路径被输出为带引号的转义形式（本地 git-bash 正常，Linux CI 直接失败）。
**修复**（`9877239`）：`git -c core.quotePath=false ls-files -z`。
**教训**：**脚本处理 git 路径必须用 `-z` + `quotePath=false`**——中文路径在 Windows 本地和 Linux CI 表现不同，是本项目的高频坑（219 个非 ASCII 路径）。
**Codex 检查**：写任何遍历 git 文件列表的脚本，一律 `git -c core.quotePath=false ls-files -z | while IFS= read -r -d '' f`。

### 12. 前端布局：网格被 nowrap 内容撑破 + reveal 元素隐形

**症状 A**：390px 移动端横向溢出 141px。
**根因**：`grid-template-columns: 1fr` 的 `1fr` 等价 `minmax(auto,1fr)`，网格项 `min-width:auto` 会被内部 `white-space:nowrap` 的 `.code` 撑破。
**修复**：所有网格改 `minmax(0, 1fr)` + 网格项 `min-width: 0`。

**症状 B**：页面滚动/锚点跳转后 `.reveal` 元素永久停在 `opacity:0`（内容隐形）。
**根因**：仅依赖 `IntersectionObserver`，锚点直达或快速滚动时可能不触发。
**修复**：加 `rAF` 节流的滚动兜底 `sweep()`，把「已进入或在视口上方」的元素直接显示。
**教训**：**滚动进场动画必须有兜底**——IO 不是 100% 可靠，缺兜底 = 内容隐形（比没动画更糟）。

## 📋 Codex 提交前自检清单（建议每次提交前跑）

```bash
# 1. 敏感文件
git ls-files | grep -iE "certdata|keystore|\.jks$|\.p12$|\.pem$|\.env$|secret|credential"

# 2. 暂存区密钥特征
git diff --cached | grep -iE "password|passwd|secret|api[_-]?key|token|Bearer" | head

# 3. 大文件（>2MB 不该进库）
git ls-files -z | xargs -0 du -k 2>/dev/null | awk '$1 > 2048 {print $1"KB\t"$2}'

# 4. 中文路径脚本安全
grep -rn "git ls-files" scripts/ tools/ .github/ | grep -v "quotePath=false"

# 5. 版本三轨一致性
diff <(cat VERSION) <(echo) >/dev/null; # 程序版本
diff <(cat CONTENT_VERSION) <(python -c "import json;print(json.load(open('content-manifest.json'))['content_version'])")
diff <(cat OFFLINE_CONTENT_VERSION) <(python -c "import json;print(json.load(open('content-manifest.json'))['offline_seed_version'])")
```
